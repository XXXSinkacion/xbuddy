## 3. 开发过程中发现并修正的问题（由测试与运行暴露）

| # | 问题 | 发现方式 | 修正 |
|---|---|---|---|
| 1 | FastAPI 在 `from __future__ import annotations` 下无法解析定义在工厂函数内部的 pydantic 请求模型，`POST /api/threads` 返回 422（body 被当成 query） | `test_api` 失败 | 请求模型移到模块级 |
| 2 | 故障注入直接返回失败，绕过了重试 / 退避路径，导致“数据源故障”演示与真实故障行为不一致，且没有 `tool.retry` 事件 | `test_fuyao_outage` 断言失败 | 注入故障改为在重试循环内生效，与真实故障同路径（重试 → 熔断 → 备用链 → 过期缓存） |
| 3 | “过期缓存兜底”测试在 fixture 模式下被新鲜缓存命中掩盖（TTL 600s 内都是 fresh hit），并未验证 stale 路径 | `test_stale_cache` 结果全为 ok | 测试显式把缓存时间戳推前 10 天后再注入故障；确认 stale 标注进入证据与报告 |
| 4 | 模板规划从“贵州茅台(600519.SH)”同时抽出代码与名称，产生两次标的检索 | 单元测试 | 保留（结果按 thscode 去重，无副作用），测试放宽，记录为已知行为 |
| 5 | 预算预警测试用“高单价”触发时，第一次模型调用就越过成本上限，直接命中停止规则而非 80% 预警 | 测试得到 `stopped` 而非 `waiting_approval` | 测试改为固定 token 用量精确控制；同时确认了“停止规则优先于预警”的策略顺序是合理的 |
| 6 | 一次性用 Bash heredoc 写多个含中文的文件时脚本解析失败（未成对引号） | 命令报错、文件未生成 | 改为逐文件写入；验证 UTF-8 字节正确 |
| 7 | 候选名称解析会把“白酒”等板块词当作标的名 | 规划器设计评审 | 加入板块关键词与停用词表，板块词只用于板块任务 |
| 8 | 模型中途不可用时，LLM 规划的任务没有可执行的后备步骤 | 设计评审 | 规划落库时为每个 LLM 任务挂载与其工具集匹配的模板流水线，执行阶段降级后可继续 |
| 9 | **熔断连坐**：某端点返回业务错误 5003（请求尚未披露的 2026-3 财务指标）后，3 次重试把“数据源级”熔断器打开，随后 30s 内同数据源全部端点被短路 | live 冒烟（真实 Key） | 熔断分两级：传输层失败（超时 / 5xx / 429）按尝试次数计入数据源级；业务错误只按“整次调用”计入端点级，不影响其它端点；新增单元测试 |
| 10 | 资产负债表 / 现金流量表摘要为空：文档推测的字段名（`total_assets` 等）与实际返回（`assets_total` / `total_debt` / `holder_equity_total` / `act_cash_flow_net`）不一致 | live 冒烟 | 按实测字段名修正摘要与 UI 表头 |
| 11 | 指数快照摘要把点位写成“元” | live 冒烟（口径复核） | 指数摘要单位改为“点”，`unit_notes` 同步 |
| 12 | 周日请求涨停池返回空，被记为 missing | live 冒烟 | 未指定日期且当日为空时回退最近交易日，所用日期写入口径与摘要 |
| 13 | **演示数据污染记忆**：fixture 模式跑出的“研究过的标的 885613.TI（演示板块代码）”被写入长期记忆，真实运行时被模型当作先验（模型用检索结果纠正了它，但不应依赖模型） | live 真实模型运行 | 来自演示数据运行的记忆提案一律加“（来源：演示数据运行，非真实行情）”并打 `demo` 标签；删除了本机的两条污染记忆 |
| 14 | **Linter 误删合规声明**：模型在摘要里写“本报告不输出涨跌预测、买卖建议或目标价”，被“目标价”规则整句移除 | live 边界用例（“茅台明天会涨吗？给我买卖建议和目标价”） | 命中前 20 字内（不跨逗号）出现否定词视为否定语境，不移除；新增测试覆盖正反例 |

### 3.1 第二轮代码审查发现并修正的问题（2026-10-26）

| # | 问题 | 发现方式 | 修正 |
|---|---|---|---|
| 15 | **路径穿越（安全）**：SPA 回退路由直接拼接用户路径，`/%2e%2e/%2e%2e/README.md` 能读到静态目录之外的文件；公开实例上同样手法可读 `/proc/self/environ`，泄露扶摇与模型密钥 | 代码审查 → 本地复现（读到 README） | 路径解析后必须位于 dist 目录内，否则 404；未知 `/api/*` 不回落到首页；回归测试覆盖三种编码。建议轮换线上密钥 |
| 16 | **证据被污染**：`get_evidence` 与 `note_fact` 标了 `no_evidence` 但仍被记录为证据；线上首份报告 19 条证据中 11 条是重复或模型笔记，模型可把自己写的 note_fact 当 [E#] 引用 | 审查线上 bundle.json | 非数据工具不生成证据；`get_evidence` 的渲染提示引用原编号；系统提示同步说明 |
| 17 | **成本漏计**：规划与报告阶段的模型调用不计入运行用量（代码里留有“简化”注释），`llm_errors` 从未累计；预算停止规则因此低估成本 | 代码审查 | 运行级统一事件出口按 `llm.end / llm.error` 累计全部模型调用；执行器不再重复累计；测试断言用量与事件逐项相等 |
| 18 | **已停止的运行可被“复活”**：对 stopped 运行点恢复（UI 也显示了按钮）会进入 running 后立即退出，状态永久卡在 running；失败运行的提示写“可点恢复”，接口却拒绝 | 代码审查 | 只允许恢复未结束的运行（中断 / 失败 / 审批已决定）；UI 按钮条件同步 |
| 19 | 运行停止后未决审批仍是 pending，之后点批准会把已结束的运行重新拉起 | 代码审查 | 停止时置为 `expired`；非等待态的审批决定直接拒绝 |
| 20 | **时长预算包含等待人工审批的时间**：计划审批放 10 分钟再批准，运行一恢复就因“达到时长上限”停止 | 代码审查 | 记录暂停起点与累计暂停时长，时长规则使用有效时长 |
| 21 | **任务小结绕过合规**：Linter 只检查最终报告，对话流里的任务小结可以出现“建议买入”或不存在的 [E#] | 代码审查 | 任务小结过同一套禁止词与引用有效性检查，事件 `compliance.task_lint` |
| 22 | **LLM 任务无证据也标 done**：工具全部失败时模型写一段小结，任务状态仍为 done（“静默正常”） | 代码审查 | 无任何成功证据 → `partial`，小结追加【系统】说明 |
| 23 | **【事实】可以只引用失败证据**：引用编号存在即通过，不看证据状态 | 对照题目“调用失败时不得静默生成正常结论” | 只引用 error / missing 证据的【事实】改标【不确定】（陈述失败本身除外）；引用过期缓存追加提示 |
| 24 | **数值无法核验**：引用只证明“指向了某条证据”，数字本身可能写错 | 对照题目“核心结论必须能回到原始字段” | 新增 `numcheck.py`：【事实】数值在所引证据（含上游）原始 JSON 中按单位换算 + 精度容差查找，核不到标“待核”；线上首份报告 48/48 核到、0 误报，46 个人为改动全部检出 |
| 25 | **二次压缩丢失早期线索**：第二次折叠时把上一轮“压缩摘要”截成 160 字，早期证据编号丢失 | 代码审查 | 上一轮摘要逐行并入（上限 80 行） |
| 26 | 模板流水线的逐步小结存在局部变量里，中途恢复后之前步骤的小结丢失 | 代码审查 | 小结随检查点持久化（`task_notes`） |
| 27 | **过期数据未识别**：停牌股的 K 线末端断档仍被当作 ok | 对照题目“过期时不得静默” | 最近一根 K 线距区间末端 > 7 天 → `partial` 并写明原因 |
| 28 | **公开实例可被拖垮**：访客注入的故障永不过期、无并发与成本上限 | 部署后审查 | 故障注入默认 300s 自动失效；全局并发上限（429）；每日模型成本上限（超出降级模板模式） |
| 29 | 记忆召回按时间而非相关度排序（“研究”等高频 2-gram 让召回接近随机），live 模式仍会召回演示数据记忆 | 代码审查 | 按命中词加权打分，偏好常驻；live 模式过滤 `demo` 记忆 |
| 30 | 时延：模型一轮返回多个工具调用时串行执行；iFinD 传输错误不计入数据源熔断；删除线程不停止其运行；`attempts` 计数不准等小问题 | 代码审查 | 同轮自动放行调用并发执行（复测 10 批并发）；其余逐项修正 |
| 31 | 数值核验把不带交易所后缀的 6 位证券代码（如“600036”）当成待核数值 | 录制演示视频时抽帧发现 | 无小数、无单位的 6 位整数视为证券代码，不参与核验；补测试 |

## 5. 关于 AI 产出的边界声明

- 扶摇 **live** 路径已于 2026-10-25 用真实 Key 实测：19 个工具全部返回 `source=fuyao` 的正常数据（`scripts/live_probe.py`），据此修正了三处文档与实际不一致的字段 / 单位（上表 10–12）。
- iFinD MCP 桥接按 MCP 标准协议实现（streamable HTTP / SSE），未与真实服务端联调；连接失败会被记录到 `/api/config` 并自动跳过。
- 真实模型验证只用了 DeepSeek（OpenAI 兼容）：4 次完整运行（预置目标、合规边界、L2 工具审批、2500 token 上下文预算触发 4 次压缩）合计约 0.07 美元。Anthropic 客户端按官方 SDK 文档编写（Messages API、工具块、thinking 块回放），默认模型 `claude-opus-5-5`，未用真实密钥实测；产品内置的模型级降级链已覆盖拒答 / 限流 / 超时，未启用服务端 `fallbacks` 参数。

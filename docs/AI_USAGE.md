## 3. 开发过程中发现并修正的问题（由测试与运行暴露）

| # | 问题 | 发现方式 | 修正 |
|---|---|---|---|
| 1 | FastAPI 在 `from __future__ import annotations` 下无法解析定义在工厂函数内部的 pydantic 请求模型，`POST /api/threads` 返回 422（body 被当成 query） | `test_api` 失败 | 请求模型移到模块级 |
| 2 | 故障注入直接返回失败，绕过了重试 / 退避路径，导致“数据源故障”演示与真实故障行为不一致，且没有 `tool.retry` 事件 | `test_fuyao_outage` 断言失败 | 注入故障改为在重试循环内生效，与真实故障同路径（重试 → 熔断 → 备用链 → 过期缓存） |
| 3 | “过期缓存兜底”测试在 fixture 模式下被新鲜缓存命中掩盖（TTL 600s 内都是 fresh hit），并未验证 stale 路径 | `test_stale_cache` 结果全为 ok | 测试显式把缓存时间戳推前 10 天后再注入故障；确认 stale 标注进入证据与报告 |
| 4 | 模板规划从“贵州茅台(600519.SH)”同时抽出代码与名称，产生两次标的检索 | 单元测试 | 保留（结果按 thscode 去重，无副作用），测试放宽，记录为已知行为 |
| 5 | 预算预警测试用“高单价”触发时，第一次模型调用就越过成本上限，直接命中停止规则而非 80% 预警 | 测试得到 `stopped` 而非 `waiting_approval` | 测试改为固定 token 用量精确控制；同时确认了“停止规则优先于预警”的策略顺序是合理的 |
| 6 | 一次性用 Bash heredoc 写多个含中文的文件时脚本解析失败（未成对引号） | 命令报错、文件未生成 | 改为逐文件写入；验证 UTF-8 字节正确 |
| 7 | 候选名称解析会把“白酒”等板块词当作标的名 | 规划器设计评审 | 加入板块关键词与停用词表，板块词只用于板块任务 |
| 8 | 模型中途不可用时，LLM 规划的任务没有可执行的后备步骤 | 设计评审 | 规划落库时为每个 LLM 任务挂载与其工具集匹配的模板流水线，执行阶段降级后可继续 |

## 5. 关于 AI 产出的边界声明

- 扶摇 **live** 路径的字段映射依据官方文档编写，并以 fixture 数据覆盖测试；真实接口的返回在提交前需用密钥实测（见第 4 节）。
- iFinD MCP 桥接按 MCP 标准协议实现（streamable HTTP / SSE），未与真实服务端联调；连接失败会被记录到 `/api/config` 并自动跳过。
- Anthropic 客户端按官方 SDK 文档编写（Messages API、工具块、thinking 块回放），默认模型 `claude-opus-5-5`；产品内置的模型级降级链已覆盖拒答 / 限流 / 超时，未启用服务端 `fallbacks` 参数。

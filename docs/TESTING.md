## 2. 手工验证脚本（UI）

前置：`docker compose up --build` 或本地启动，打开工作台。无任何密钥时运行在「模板模式 + 演示数据」，所有步骤同样可走通（证据会标注演示数据）。

### 2.1 主链路（核心任务）
1. 点击预置目标「研究贵州茅台(600519.SH)近3个月行情、估值与最新财务指标，并与白酒板块对比」→「开始研究」。
2. 观察：对话流出现**计划卡片**（任务 / 工具 / 验收）；顶栏活动行滚动显示工具调用与证据编号；右栏「任务」状态逐个变绿；「证据」逐条增加（来源 / 时点 / 单位 / 原始 JSON）。
3. 完成后出现**报告卡片**，点「查看报告」：核心结论每条带【事实 / 推断 / 不确定】与 `[E#]`，点击 `[E#]` 打开证据原始字段；「数据口径与时点」「数据缺失与限制」「证据清单」「免责声明」齐全；可下载 `.md` 与证据包 `.json`。
4. 出现「是否写入长期记忆」审批卡片 → 批准 → 右栏「记忆」可见新条目。
5. 在同一线程再输入「上述标的的 ROE 与毛利率对比」→ 规划阶段注入线程历史（观测页 `memory.recalled`）。

### 2.2 审批 / 权限
1. 「⚙ 预算与审批」把计划确认改为 `always` → 发起研究 → 计划审批卡片；在备注填「去掉 t3」批准 → 任务 t3 显示跳过。
2. 再次发起并**拒绝**计划 → 运行状态 `stopped`，仍产出标注“运行未完成”的部分报告。
3. 配置模型后，目标写「研究贵州茅台并把它加入我的自选」→ 执行器调用 `add_to_watchlist`（L2）触发工具审批；拒绝 → 继续完成且记忆无新增。

### 2.3 停止规则 / 预算
1. 「⚙」把最大工具调用设为 3 → 发起 → 运行 `stopped`，停止原因“达到工具调用上限 3”，报告标注未完成。
2. 成本上限设很小（如 0.001，需配置模型）→ 触发 80% 预警审批 → 批准后预算翻倍继续 / 拒绝则停止。
3. 运行中点「■ 停止」→ 立即收尾并产出部分报告。

### 2.4 数据缺失 / 接口失败 / 降级恢复
1. 顶栏「故障注入」选 `fuyao: 报错` → 发起研究 → 活动行可见重试；证据全部 `error`；报告「核心结论」只有【不确定】，「数据缺失与限制」逐条列出；观测页可见熔断器 `open`。
2. 选 `fuyao: 正常`，30s 内再跑 → 熔断半开后恢复；先前成功过的同参数调用若再次故障会以「过期缓存（stale）」返回并在报告标注。
3. 选 `llm: 报错`（需配置模型）→ 运行降级为模板模式（顶栏芯片变为「模板模式」，观测页 `run.degraded`），仍完成。
4. 输入不存在的标的「研究不存在公司甲乙丙的估值」→ 检索证据 `missing`，报告给出【不确定】。

### 2.5 检查点与恢复
1. 发起研究后立刻重启后端进程（Ctrl+C 再启动）→ 刷新页面，运行状态 `interrupted`，顶栏出现「▶ 从检查点恢复」→ 点击 → 从中断任务继续，已完成任务不重跑，证据编号连续。
2. 观测页「检查点」计数随步骤增长。

### 2.6 极端 / 合规边界
1. 目标写「茅台明天会涨吗？给我买卖建议和目标价」→ 计划不包含预测任务；报告与任务小结若出现违规表述会被 Linter 移除并在报告卡片显示“已修正”。
1a. 打开任一报告：卡片显示「数值核验 x/y」；核不到的数值在正文对应要点末尾标“〔待核数值：…〕”（效果见 `test_review_fixes.py::test_numeric_verification_flags_numbers_not_in_cited_evidence`）。
2. 把上下文预算设为 2000 tokens（需配置模型）→ 观测页出现 `context.compressed`，任务仍能用 `get_evidence(E#)` 取回原文。
3. 连续重复同一工具调用（模型异常时）→ 第 3 次被拦截（`tool.loop_blocked`）。
4. 空目标 / 线程内并发发起 → 接口分别返回 400 / 409。
